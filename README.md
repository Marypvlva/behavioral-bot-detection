# Behavioral Bot Detection

Детекция автоматизированного поведения по журналам пользовательских событий.

Компактный ML-пайплайн для выявления ботов на основе поведенческих паттернов, временной структуры событий и технического окружения пользователя.

Финальная модель использует **14 интерпретируемых признаков** и `HistGradientBoostingClassifier` для ранжирования пользователей по вероятности автоматизированного поведения.

---

## Задача

Данные представлены на двух уровнях:

- одна строка на `cookie_id` с временным окном наблюдения;
- журнал событий с поиском, просмотрами объявлений, координатами указателя, платформой и строкой `User-Agent`.

Цель — для каждого `cookie_id` получить `score` в диапазоне `[0, 1]`, отражающий вероятность автоматизированного поведения.

Основная метрика:

**Precision при Recall ≥ 0.70**

Поэтому ключевая задача модели — не просто правильно классифицировать пользователей, а качественно ранжировать их в области высокой полноты.

---

## Почему используется временная валидация

Для событийных данных случайное разбиение может давать слишком оптимистичную оценку качества, поскольку события из будущего могут косвенно влиять на обучение.

Используются два хронологических holdout-разбиения:

- последние **7 дней** обучающего периода — основная валидация;
- последние **3 дня** — дополнительная проверка стабильности.

Основным критерием выбора модели служит 7-дневный сплит, так как он лучше отражает работу модели на последующем временном периоде.

---

## Подготовка данных

В обработку попадают только события, произошедшие внутри окна наблюдения конкретного пользователя:

```text
window_start_ts <= event_ts < window_end_ts
```

Удаляются только полные дубликаты строк.

События с одинаковыми `event_ts` и `eid`, но различающимися остальными полями, сохраняются, поскольку они могут отражать различные действия пользователя.

---

## Построение признаков

Финальное решение использует **14 признаков**, объединённых в несколько смысловых групп.

### Временная активность

- `delta_le_60_share` — доля соседних событий с интервалом не более 60 секунд;
- `sessions_30m_mean` — среднее число событий в сессии, где новая сессия начинается после паузы более 30 минут;
- `created_recent_7d` — был ли cookie создан менее чем за 7 дней до начала окна наблюдения.

### Поведение указателя

- `pointer_x_std` — разброс координат указателя по горизонтали;
- `pointer_y_range` — диапазон перемещений указателя по вертикали.

### Разнообразие контента

- `category_entropy` — энтропия просмотренных категорий;
- `item_entropy` — энтропия просмотренных объектов;
- `location_entropy` — энтропия локаций;
- `category_unique_ratio` — доля уникальных категорий;
- `search_page_value_q90` — 90-й перцентиль глубины просмотра поисковой выдачи.

### Последовательности событий

- `tr_item_item` — доля переходов `item_view → item_view` среди последовательных событий пользователя.

### Разнообразие технического окружения

- `ua_browser_nunique` — число различных семейств браузеров внутри одного cookie;
- `ua_platform_nunique` — число различных нормализованных платформ;
- `ua_nunique` — число уникальных полных строк `User-Agent`.

Набор признаков формировался постепенно: новые признаки проверялись на временной валидации и сохранялись только в том случае, если давали устойчивый дополнительный сигнал.

---

## Сравнение моделей

Несколько алгоритмов были проверены на одном и том же компактном наборе признаков.

| Модель | Валидация 3 дня | Валидация 7 дней |
|---|---:|---:|
| HistGradientBoosting | 0.6726 | 0.6560 |
| Balanced Random Forest | 0.6667 | 0.6172 |
| Random Forest | 0.6512 | 0.5971 |
| Extra Trees | 0.6552 | 0.5946 |
| Logistic Regression | 0.2358 | 0.2201 |

Большой разрыв между линейной моделью и деревьями показывает, что полезный сигнал в данных в значительной степени нелинейный и зависит от взаимодействий между признаками.

В качестве финальной модели выбран `HistGradientBoostingClassifier`: он показал лучшее сочетание качества, компактности и воспроизводимости.

---

## Как развивалось решение

| Набор признаков | Валидация 3 дня | Валидация 7 дней |
|---|---:|---:|
| Базовые 9 признаков | 0.6726 | 0.6560 |
| + диапазон pointer по Y | 0.6957 | 0.6590 |
| + последовательные `item_view` | 0.6826 | 0.6729 |
| + разнообразие User-Agent | 0.7044 | 0.6850 |

Финальная внешняя оценка модели:

**0.64542 по метрике `Precision@Recall>=0.70`**

## Финальная модель

```python
HistGradientBoostingClassifier(
    learning_rate=0.04,
    max_iter=300,
    max_leaf_nodes=15,
    min_samples_leaf=20,
    l2_regularization=5,
    random_state=0,
)
```

После выбора признаков и параметров модель переобучается на всех доступных размеченных данных.

Результат сохраняется в:

```text
submission_final.csv
```

## Основные выводы

- для событийных данных с временной структурой хронологическая валидация надёжнее случайного разбиения;
- компактный набор осмысленных поведенческих признаков может быть полезнее большого количества слабых фичей;
- порядок событий содержит дополнительную информацию, которую не видно в простых агрегатах;
- разнообразие `User-Agent` и платформ внутри одного cookie может отражать нестабильность технического окружения;
- градиентный бустинг лучше линейной модели улавливает нелинейные взаимодействия между такими признаками.

---

## Ограничения

Часть признаков и гиперпараметров многократно проверялась на одних и тех же временных holdout-разбиениях, поэтому локальная оценка может быть немного оптимистичной.

По этой причине финальный пайплайн остаётся намеренно компактным и не использует агрессивный перебор большого числа признаков и конфигураций.

Исходные данные в репозиторий не включаются.
